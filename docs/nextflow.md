# Nextflow DSL2 target

Sophios can compile supported flat workflows to a validated Nextflow
intermediate representation and deterministic DSL2 artifacts. CWL remains the
canonical compiler representation; the Nextflow target converts the compiler's
already-inferred workflow graph without running inference a second time.

## Python API

```python
from sophios.api.python.workflow import Workflow

workflow: Workflow = build_workflow()
nextflow_ir = workflow.compile(target="nextflow")
json_path, script, config, params = workflow.to_nextflow("autogenerated")
```

Calling `workflow.compile()` or `workflow.compile(target="cwl")` continues to
return `CompiledWorkflow`. The Nextflow target returns
`ExecutableNextflowWorkflow`, a closed, immutable representation with typed
command tokens, ports, resources, and connections. Its versioned JSON form is
validated again during hydration.

## Command line

```console
sophios --yaml workflow.wic --target nextflow
```

The command writes four files beneath `autogenerated/`:

- `nextflow_workflow.json`
- `workflow.nf`
- `nextflow.config`
- `nextflow_params.json`

Run the result with a compatible Nextflow installation:

```console
nextflow run autogenerated/workflow.nf \
  -params-file autogenerated/nextflow_params.json \
  -c autogenerated/nextflow.config
```

Sophios rejects `--target nextflow` when it is combined with any CWL-specific
input, generation, or execution mode: `--generate_cwl_workflow`, `--run_local`,
`--generate_run_script`, or `--inputs_file`.

## Importing supported DSL2

```python
from sophios.api.python.nextflow import (
    import_nextflow,
    parse_nf_file,
    promote_nextflow_document,
    render_nextflow_document,
)

document = parse_nf_file("workflow.nf")
same_source = render_nextflow_document(document)
executable = promote_nextflow_document(document)
sophios_workflow = import_nextflow("workflow.nf")
```

The reader returns a `NextflowDocument`: a loss-aware structural view, not an
executable program. It recognizes the process ports, scripts, containers,
CPU/memory directives, named workflow calls, direct process-output edges, and
entry wrapper emitted by Sophios. Unknown process or workflow content is
retained in `opaque_regions` and reported during structural import.
Structural rendering returns the original source bytes as text, including
opaque regions; it does not regenerate them from inferred meaning.

Promotion is deliberately provenance-bound. It succeeds only when the source,
parameters, and adjacent `nextflow_workflow.json` exactly agree with artifacts
written from validated executable IR. Parsed source alone is never promoted by
guessing shell or Groovy semantics; changed source, changed parameters, unknown
content, and invalid or stale IR fail closed.

## Phase 1 limits

- Workflows must be flat and use `CommandLineTool`-equivalent processes.
- Boolean `inputBinding` flag semantics and fractional CPU requirements reject
  before lowering; they are not silently stringified or rounded.
- Scatter is retained as opaque structure; executable scatter is deferred.
- Nested workflows, arbitrary Groovy, channel operators, `when`, and `exec`
  blocks are not interpreted.
- Structurally imported scripts remain opaque. CWL/Sophios import preserves representable
  names, ports, resources, and topology but does not promise executable
  equivalence for arbitrary shell or Groovy semantics.
