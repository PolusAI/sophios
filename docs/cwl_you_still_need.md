# The CWL You Still Need

`sophios.api.python.tool_builder` writes the CWL YAML of a tool for you. It does
not change what that YAML means: the runner still runs the tool by CWL's rules,
and a tool that ignores them fails at run time. This page covers the CWL a
Python author still has to understand, one concept per section, each with the
builder call that writes it and an example that uses it. Every method named here
documents the CWL field it writes in the [Python API Reference](python_api_reference.rst),
and the [CWL v1.2 CommandLineTool specification](https://www.commonwl.org/v1.2/CommandLineTool.html)
is the full story.

The examples build on each other: run them in order, from the root of the
Sophios repository. They assume [Building Tool Contracts in Python](tool_builder_sam3.md).

## Expressions

A string that holds `$(...)` or `${...}` is evaluated by the runner, when the tool
runs. There are three spellings:

- `$(inputs.reads.nameroot)` reads a value. Such a parameter reference sees
  `inputs`, `self` (the value being bound, or in `outputEval` the matched files)
  and `runtime` (`runtime.cores`, `runtime.ram`, `runtime.outdir`, `runtime.tmpdir`).
- `$(self * 1024)` is a JavaScript expression.
- `${ return self[0].size > 0; }` is the body of a JavaScript function.

JavaScript needs an `InlineJavascriptRequirement`. The builder adds one whenever
any field of the tool holds `$(` or `${`, so call `inline_javascript()` only to
give it an `expressionLib`. To Python and to `validate()` an expression is only
text: `$(inputs.read)`, for an input named `reads`, is found by the runner.

```python
from sophios.api.python.tool_builder import CommandLineTool, Input, Inputs, Output, Outputs, cwl

inputs = Inputs(
    reads=Input(cwl.file, position=2),
    memory_gb=Input(cwl.int, flag="-m", value_from="$(self * 1024)M", default=2),
)
outputs = Outputs(
    sorted_reads=Output(cwl.file, glob="$(inputs.reads.nameroot).sorted.bam"),
)
sort = (
    CommandLineTool("sort_reads", inputs, outputs)
    .base_command("samtools", "sort")
    .argument("$(inputs.reads.nameroot).sorted.bam", prefix="-o", position=1)
)
```

In a workflow, Sophios adds the `InlineJavascriptRequirement` itself for a step's
`when` and for a `StepInput` whose `value_from` holds an expression, and the
`StepInputExpressionRequirement` for any `value_from`; see
[A conditional step](cookbook.md#a-conditional-step).

## Where outputs come from

When the tool exits, the runner collects each output from the tool's output
directory, which is also its working directory:

- `glob` is matched there; a pattern or an expression such as
  `$(inputs.out.basename)`. A file the tool writes elsewhere, such as
  `/tmp/result.csv`, is never collected.
- A `File` output that matches nothing fails the step, and so does one that
  matches more than one file. `required=False` makes no match a `null`;
  `cwl.array(cwl.file)` collects every match.
- `load_contents=True` reads the first 64 KiB of each match into its `contents`,
  and `output_eval` turns the matches (`self`) into the output's value.
- `Output.stdout()` and `Output.stderr()` are the captured streams. Name the
  files with `.stdout(...)` and `.stderr(...)`.

```python
outputs = Outputs(
    table=Output(cwl.file, glob="results/summary.csv"),
    plots=Output(cwl.array(cwl.file), glob="*.png"),
    count=Output(cwl.int, glob="count.txt", load_contents=True,
                 output_eval="$(parseInt(self[0].contents))"),
    log=Output.stderr(),
)
report = CommandLineTool("report", Inputs(), outputs).base_command("make_report").stderr("report.log")
```

[How to think about outputs](tool_builder_sam3.md#how-to-think-about-outputs) shows
a directory output, and [A named workflow output](cookbook.md#a-named-workflow-output)
uses `echo`'s captured standard output.

## File objects

A `File` value is a mapping, not a path. It has `class: File` and a `location`;
the runner fills in `path`, `basename`, `nameroot`, `nameext`, `dirname`, `size`
and `checksum`, which expressions read. In Python, a `File` literal is that
mapping; give an absolute `location`, since a relative one is read from the
generated job file under `autogenerated/`.

- The runner stages each input file read-only, in a directory of its choosing.
  `.stage(inputs.x)` puts it in the working directory, and `writable=True` lets
  the tool change it there.
- `secondaryFiles` travel with the file: `.bai` names `sample.bam.bai`, and `^.bai`
  replaces the extension, `sample.bai`. On an input they are required unless
  `secondary_file(".bai", required=False)`: without `sample.bam.bai`, a run of
  the workflow below stops before the tool starts.
- `format` names the file format with an ontology term, such as
  `edam:format_2572` for BAM. `.edam()` declares the `edam` prefix. A file given
  to an input that declares a `format` must carry one too, with the same name,
  or the runner refuses it.

```python
from pathlib import Path

from sophios.api.python.tool_builder import secondary_file
from sophios.api.python.workflow import Step, Workflow

index_stats = (
    CommandLineTool(
        "index_stats",
        Inputs(bam=Input(cwl.file, position=1).format("edam:format_2572").secondary_files(secondary_file(".bai"))),
        Outputs(stats=Output.stdout()),
    )
    .base_command("samtools", "idxstats")
    .stdout("$(inputs.bam.nameroot).idxstats.txt")
    .edam()
)
stats = Step(index_stats)
stats.inputs.bam = {"class": "File", "location": str(Path("sample.bam").resolve()), "format": "edam:format_2572"}
compiled = Workflow([stats], "bam_stats").compile()
```

The [SAM3 example](tool_builder_sam3.md#the-sam3-example) stages a writable
output directory.

## Types

| CWL | Builder | Type string |
| --- | --- | --- |
| `int`, `string`, `File`, `Directory`, ... | `cwl.int`, `cwl.string`, `cwl.file`, `cwl.directory`, ... | `"int"`, `"File"` |
| optional | `required=False`, `cwl.optional(t)` | `"int?"` |
| array | `cwl.array(t)`, `Input.array(t, ...)` | `"File[]"` |
| enum | `cwl.enum("a", "b")`, `Input.enum("a", "b", ...)` | |
| record | `cwl.record(Fields(...))`, `Input.record(...)` | |
| any value | | `"Any"` |

```python
from sophios.api.python.tool_builder import Field, Fields

region = cwl.record(Fields(chrom=Field(cwl.string), start=Field(cwl.int), end=Field(cwl.int)), name="Region")
inputs = Inputs(
    mode=Input.enum("fast", "sensitive", flag="--mode"),
    regions=Input(cwl.array(region), required=False),
    label=Input("string?", flag="--label"),
)
```

Types also decide inference. A step input that nothing binds is connected to an
earlier output whose type is the same, or a member of the same union, and whose
`format` matches when the input declares one. `Any` matches only `Any`, and a
`File` output without a `format` never feeds an input with one. Give outputs the
exact type and format of what the tool writes; bind an `Any` input explicitly.
[Inference](cookbook.md#inference) and
[What inference does](language_guide.md#8-what-inference-does-and-how-to-pin-it)
show the rule.

## Containers

`.docker(image)` writes `dockerPull`. Before a run, Sophios pulls every
`dockerPull` image afresh, so the image must be in a registry; an image built
only on your machine fails that pull. For such an image write `dockerImageId`
alone, `.docker(docker_image_id="my-tool:dev")`: the pull skips it, saying it has
no `dockerPull`, and the runner uses the local image as it is.

With `--container_engine podman` the pull is done by podman. A tool that ships
its image, with `dockerLoad` (a file or an http(s) URL) or `dockerImport` (with
`dockerImageId`), has it loaded into the engine before the run, since the run
itself never pulls. A pull, load or import that fails stops the run with
`wic037`, quoting the engine's last line.

The runner starts the container with the tool's command line as the arguments of
the image's `ENTRYPOINT`, if it has one. Give the full command in
`.base_command(...)`, from an image without an entrypoint;
`--docker_remove_entrypoints` rebuilds local images without theirs, to show
which tools depend on one.

`.gpu(...)` writes cwltool's `cwltool:CUDARequirement`, as a hint. As a
requirement (`as_hint=False`), `validate()` rejects it, since cwltool loads it
only with `--enable-ext`, which Sophios passes when it runs cwltool.

```python
sort.docker("quay.io/biocontainers/samtools:1.21--h50ea8bc_0")
report.docker(docker_image_id="make-report:dev").gpu(cuda_version_min="11.7", device_count_min=1)
```

## Resources, environment, network, time limits

```python
(
    sort.resources(cores=4, ram=16000)
    .env_var("OMP_NUM_THREADS", "$(runtime.cores)")
    .network_access(True)
    .time_limit(3600)
)
```

- `.resources()` writes a `ResourceRequirement`. `ram`, `tmpdir` and `outdir` are
  in mebibytes; `$(runtime.cores)` and `$(runtime.ram)` read what the runner
  granted.
- The tool does not see your shell's environment. cwltool sets `HOME` and
  `TMPDIR`, and `PATH` outside a container; anything else the tool needs goes in
  `.env_var()`.
- A builder tool is CWL v1.2, where a tool has no network unless it declares
  `NetworkAccess`: in a container, cwltool runs it with `--net=none`. Call
  `.network_access(True)` for a tool that downloads.
- `.time_limit(seconds)` writes a `ToolTimeLimit`; the runner stops the tool
  when the time is up, and the step fails.

## Multiple sources

A step input fed by several outputs is CWL's `WorkflowStepInput` with a list
`source`, written in Python as `StepInput` and in a `.wic` as `!cwl {...}`.
Sophios adds the `MultipleInputFeatureRequirement`. `link_merge` (`linkMerge`)
says how the values combine: `merge_nested`, the default, makes a list with one
entry per source, and `merge_flattened` concatenates arrays.
[A step-input record](cookbook.md#a-step-input-record) merges two files into one
`File[]`. `pick_value` (`pickValue`) chooses among sources of conditional steps,
which give `null` when they do not run: `first_non_null`, `the_only_non_null` or
`all_non_null`.

```python
from sophios.api.python.workflow import StepInput

adapters = Path("cwl_adapters")
hello = Step(clt_path=adapters / "echo.cwl", step_name="hello")
hello.inputs.message = "Hello"
goodbye = Step(clt_path=adapters / "echo.cwl", step_name="goodbye")
goodbye.inputs.message = "Goodbye"
show = Step(clt_path=adapters / "cat.cwl")
greet = Workflow([hello, goodbye, show], "greet")
hello.inputs.polite = StepInput(source=greet.inputs.polite)
hello.when = "$(inputs.polite)"
goodbye.inputs.polite = StepInput(source=greet.inputs.polite)
goodbye.when = "$(!inputs.polite)"
show.inputs.file = StepInput(source=[hello.outputs.stdout, goodbye.outputs.stdout], pick_value="the_only_non_null")
```

## What the runner reports

The compiled CWL renames each step `<workflow>__step__<n>__<id>`, and a port
exposed as a workflow input or output `<renamed step>___<port>`. The runner only
knows these names. When Sophios compiles to disk (`--generate_cwl_workflow`,
`--run_local`, `Workflow.run()`), it writes `autogenerated/<workflow>.names.json`,
which maps each one back to what you wrote: the step's position, name, file and
line, and the port's step and name. During a run with cwltool, its messages name
each step both ways. On a machine without `samtools`, a run of the `bam_stats`
workflow above ends with:

```text
ERROR 'samtools' not found: [Errno 2] No such file or directory: 'samtools'
ERROR [step 1 'index_stats' (bam_stats__step__1__index_stats)] Output is missing expected field ...
```

A failed run says where the map is. `autogenerated/output_<workflow>.json` lists
the run's outputs: a workflow output you named appears under your name, and step
outputs under their renamed form. [Generated Files](userguide.md#generated-files)
lists everything a run writes.
