# Real-time analysis

How do I look at a step's results while it is still running? A real-time
analysis is an ordinary tool or `.wic` workflow that Sophios runs on the host
beside the workflow: each time the files it watches change, when the step
writing them finishes, and once more when the workflow ends. Use it to plot
the progress of a long simulation before it ends, or to check an intermediate
result and stop a run that has gone wrong.

## Declaring one

An analysis is declared as a step that runs the `cwl_subinterpreter` adapter,
which ships with Sophios in `cwl_adapters/file_watchers/`:


```{literalinclude} cookbook/watched.py
:language: python
:caption: watched.py
```

Here `cat` runs on `greeting.txt` as the workflow writes it. The declaration's
inputs, every one a literal:

| Input | Meaning |
|---|---|
| `file_pattern` | a glob, matched against the names of the files the workflow's steps write: `'*prod.trr'` |
| `cwl_tool` | the analysis: a tool on the search paths, by stem, or a `.wic` workflow, with its extension |
| `max_times` | the most times the analysis runs, the final run included |
| `interval` | the fewest seconds between two runs triggered by a change; 60 when not given |
| `config` | for a tool, the step's own keys, such as `in:`; for a `.wic`, its `wic: steps:` entries. Every `in:` value is a literal, and a file is named by its basename |

`cwl_tool` names the analysis by registry stem, and a `.wic` analysis is
found on `search_paths_wic` like a subworkflow. The command line reads both
from the configuration. `Workflow.run()` reads no configuration, so from Python
the analysis's tool must be one of the workflow's own tools or be in the
`tool_registry=` given to `run()`, as `watched.py` does with
`plugins.get_tools_cwl(input_output.get_config(None, Path.home()))`; a `.wic`
analysis is given as `run(workflow_paths=...)`, shaped `{namespace: {stem: path}}`
like `Workflow.from_wic(workflow_paths=...)`. An analysis the run cannot find is
`wic044` at the declaration.

## What happens at compile time

The declaration is checked and taken out of the workflow: the compiled CWL
does not contain it, inference never wires it, and `write_wic()` writes it
back as a declaration (`run: cwl_subinterpreter`). The analysis is compiled
once, as a one-step workflow, to `autogenerated/realtime/<name>/`, where
`<name>` is the declaring workflow's name, and listed in
`autogenerated/<workflow>.realtime.json`:

```json
[
  {
    "name": "watched",
    "analysis": "cat",
    "file_pattern": "greeting.txt",
    "max_times": 3,
    "interval": 60,
    "cwl": "realtime/watched/cat_only.cwl",
    "inputs": "realtime/watched/cat_only_inputs.yml",
    "root_dir": "/.../sophios-examples",
    "declared_at": "watched.wic:8:3"
  }
]
```

A declaration with an input that is not a literal or has the wrong shape, or
whose analysis does not compile, is `wic044` at the declaration, before
anything runs; the message carries the analysis's own diagnostics. Two
declarations in one workflow are named `<workflow>` and `<workflow>_2`.

## What happens at run time

With `--run_local` and cwltool, or `Workflow.run()`, Sophios runs one watcher
per declaration:

- The run caches its jobs (`--cachedir`, in `cachedir/` unless you named
  one), so that each step runs in a directory of its own under it. The
  watcher polls the job directories of this run every two seconds; jobs from
  earlier runs and cache hits never trigger it. Polling is deliberate:
  file-change notifications miss changes on network filesystems and
  container mounts, which is where long jobs write.
- The analysis runs when a watched file changed and `interval` seconds have
  passed since the last run started; at once when the step holding a watched
  file finishes; and once more when the workflow ends, if anything changed
  since the last run and that step did not fail. Changes during a run make one
  follow-up run. `max_times` caps the total.
- Each file the analysis reads is the newest file of that name written by a
  step of this run; else one an earlier run left in the cache, which a cache
  hit this run reused; else the file of that path beside the root workflow.
  When it is in none of them, that run is skipped with one line naming the
  file. A name written by several jobs is reported, and the newest is used.
- The analysis's images are pulled with the workflow's, and it runs with the
  same container engine, in a subprocess of its own.
- Each run's outputs and log are in `cachedir/realtime/<name>/run-NNN/` and
  `run-NNN.log`, numbered on from an earlier run of the workflow in the same
  cache, and one line per run reports how it went. A failed analysis never
  changes the workflow's outcome. The run ends with a count:

```text
real-time analysis watched (cat): run 1 (the workflow finished) finished in 2 s
real-time analysis watched (cat): 1 runs, 1 succeeded
```

To plot as results arrive, point a plotter at the cache directory; each run's
outputs are files like any other.

## When it does not run

The analysis needs cwltool's cache and a run Sophios itself conducts. With
`--generate_run_script`, `run.sh` runs the workflow without its analyses, and
with `--cwl_runner toil-cwl-runner` so does Toil; in both cases a line on
stderr says so, and the workflow is otherwise unchanged. `--check` and
`--generate_cwl_workflow` compile the analysis and write it under
`autogenerated/realtime/`, so a declaration is validated whether or not it
will run.
