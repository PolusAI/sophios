# Git etiquette

How are changes to Sophios branched, committed and merged? Work happens on
short-lived branches of a fork, proposed to `PolusAI/sophios` as pull
requests against `master`, and reviewed before they land.

## Branches

One branch per change, made from the current `master` and named for its type
and subject (`fix/scatter-rank`, `docs/edge-inference`). A branch that grows
a second concern is split. Long-lived branches are rebased onto `master`
rather than merged from it, so that their history stays linear and their
review stays about the change.

## Commits

Commits follow [Conventional Commits](https://www.conventionalcommits.org/):
a type (`feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`), an optional
scope, and an imperative subject of about fifty characters, with a short body
that says why. release-please reads them: the version and the changelog of a
release are derived from the commits since the last one, so a `feat` and a
`fix` mean something to the next release and a `chore` does not.

A commit is one logical change, easy to review and easy to revert. Fix-ups to
your own unpushed commits are folded in, not stacked on top. The pre-commit
hooks run the formatting and type checks on each commit.

## Pull requests

A pull request is one change, with its tests, described by what it does and
why. CI runs on a push to the fork; the lanes compile the workflow corpora,
run the suite, type-check, lint and build these docs, and a pull request is
merged only green. A problem found in review is fixed on the branch and
pushed again.

Pull requests land as rebase merges, keeping their commits on `master`
without a merge commit. Branches whose base is a long-lived feature branch
are synchronised from `master` with a merge commit instead, so that the
feature branch keeps the history it was reviewed with.

## Staging

Run `git status` before staging and add files by name. The compiler writes
`autogenerated/`, `cachedir/` and runner output beside your sources, and a
test run writes more; `.gitignore` covers the usual names, and `git add .`
will still find something it should not.
