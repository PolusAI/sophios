# Drawing a workflow

How do I see the graph Sophios compiled, with the edges it inferred? `--graphviz`
draws it, as a Graphviz source and a PNG, beside the compiled CWL. Look at the
drawing before a long run: an inferred edge that went to the wrong step is
obvious in a picture and invisible in a log.

## Drawing

```bash
sophios --yaml greeting.wic --generate_cwl_workflow --graphviz
```

The flag combines with any of the four commands and writes three files under
`autogenerated/`:

| File | What |
|---|---|
| `<workflow>.wic.gv` | Sophios's drawing, as Graphviz source |
| `<workflow>.wic.gv.png` | the same, rendered with `dot` |
| `<workflow>.svg` | cwltool's own drawing of the compiled CWL, for comparison |

The `dot` program comes with Graphviz; without it on your `PATH` Sophios
prints a `wic029` note, compiles without the drawing, and goes on. Drawing is
a command-line feature; a Python workflow is drawn by writing it out with
`write_wic()` and compiling the bundle with `--graphviz`.

## Reading the drawing

![multistep1, with explicit edges](tutorials/multistep1.wic.gv.png)

![multistep2, with inferred edges](tutorials/multistep2.wic.gv.png)

The two drawings are `docs/tutorials/multistep1.wic`, whose every edge is
written with `!&` and `!*`, and `multistep2.wic`, the same four steps with
every edge left to inference. Each step is a box labelled with its id, and
each workflow a cluster labelled with its file name. An explicit edge is
blue; an inferred edge takes the drawing's foreground colour, white on the
transparent background, or black with `--graph_dark_theme`, so that a reader
can tell what the document said from what the compiler decided. The graphs are
the same, which is what inference is for.

One edge is drawn per pair of steps, however many ports connect them.

## Options

| Flag | Effect |
|---|---|
| `--graph_label_edges` | one edge per port, labelled with the name of the output it carries |
| `--graph_label_stepname` | label each box with its generated step name (`greeting__step__1__touch`) instead of its id or its `wic: graphviz: label` |
| `--graph_inline_depth N` | draw the steps of subworkflows nested up to depth `N`; a deeper call is one box |
| `--graph_dark_theme` | black text and inferred edges, for a light background |

## Labels and layout from the `.wic` file

The `wic:` block's `graphviz` key changes only the drawing:

```yaml
wic:
  graphviz:
    label: Make and print a file
    ranksame:
    - (1, touch)
    - (3, cat)
  steps:
    (1, touch):
      wic:
        graphviz:
          label: create the file
          style: dashed
steps:
- id: touch
  in:
    filename: !ii empty.txt
- id: append
  in:
    str: !ii Hello
- id: cat
```

- `label` on a step replaces its id as the label of its box; write `\n` for a
  line break. `--graph_label_stepname` overrides it with the generated name.
- `label` on a workflow, or on the `wic: steps:` entry that calls it, titles
  the workflow's cluster. A subworkflow without one is titled with the id it
  is called by.
- `style` on a step is appended to the box's own `rounded, filled`; on a
  workflow it styles the cluster, and `invis` hides the cluster and the box of
  the step that calls it.
- `ranksame` lists steps of this document, as `(index, name)`, to draw on one
  rank. An entry that addresses no step is ignored, with a line on stderr.

`from_wic()` drops these keys with a warning, since a Python workflow has no
drawing of its own; `write_wic()` writes none.
