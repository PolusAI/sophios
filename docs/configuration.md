# Configuration

Sophios's configuration is one JSON file, `~/wic/global_config.json`. It
says where `.wic` steps find their tools and the `.wic` files they call, and
holds two settings for [edge inference](edge-inference.md). This page shows
you how to add a directory of your own tools, how Sophios searches, and what
the Python API takes from the configuration and what it is given directly.
[Configuration reference](configuration-reference.md) lists every key.

## The file

```json
{
    "search_paths_cwl": {
        "global": ["/home/you/wic/cwl_adapters"],
        "gpu": []
    },
    "search_paths_wic": {
        "global": ["/home/you/wic/examples"]
    },
    "renaming_conventions": [
        ["energy_", "edr_"],
        ["structure_", "tpr_"],
        ["traj_", "trr_"]
    ],
    "inference_rules": {
        "edam:format_3881": "continue",
        "edam:format_3987": "continue",
        "edam:format_3878": "break",
        "edam:format_2033": "break"
    }
}
```

This is what `sophios --generate_config` writes, and what the first `sophios`
command writes when the file does not exist yet, after copying the tools and
example workflows that ship with Sophios to `~/wic/cwl_adapters` and
`~/wic/examples`. From a source checkout the copies come from the checkout's
`cwl_adapters/` and `docs/tutorials/`. An existing file is never overwritten;
`--generate_config` says so and exits.

`--config_file <file>` names another file to read, which must exist; it is
only ever read, never generated. `--homedir <dir>` moves the default to
`<dir>/wic/global_config.json`. Relative paths in a configuration file are
resolved from the working directory, so write absolute ones.

## Search paths

`search_paths_cwl` is where `.wic` steps find their tools, and
`search_paths_wic` where they find the `.wic` files they call. Each is a
mapping of namespaces to lists of directories.

## Add a directory of your own tools

1. Put your tool files in a directory of their own, for example
   `~/my-tools/`, with `word_count.cwl` from
   [Steps and tools](steps-and-tools.md) in it.
2. Open `~/wic/global_config.json` and add the directory, as an absolute
   path, to the `global` list of `search_paths_cwl`:

   ```json
   "search_paths_cwl": {
       "global": ["/home/you/wic/cwl_adapters", "/home/you/my-tools"],
       "gpu": []
   }
   ```

3. Check: a `.wic` step can now name the tool by its stem, `- id: word_count`,
   with no `run:`. Compile a workflow that does, with
   `sophios --yaml <workflow>.wic --generate_cwl_workflow`; a stem Sophios
   cannot find is `wic013`.

A directory of `.wic` workflows goes under `search_paths_wic` the same way,
which is how [Subworkflows](subworkflows.md) finds `make_greeting.wic`.

## How Sophios searches

- Every directory is searched recursively, for `*.cwl` or `*.wic`, and the
  files are indexed by stem; a `.wic` is read only when a workflow calls it.
  A `.wic` file whose path contains `_inputs` is skipped as a job file;
  a `.cwl` tool named `*_inputs.cwl` is loaded like any other.
- A stem is a name: `touch` is `touch.cwl` wherever it sits. A stem found
  twice in one namespace prints a warning naming both files and the one
  used, and the later definition wins: search paths in the order the
  configuration lists them, then files in sorted path order. To use the
  other, list its directory later, rename one, or give it its own namespace.
- Below a search path, nothing under a directory named `autogenerated/` is
  found, and nothing under the base path in use, when `--basepath` or
  `basepath=` puts it there. So the CWL Sophios generates beside your sources
  is never picked up as a source. A base path that is the search path itself
  hides nothing.
- A directory with no `.cwl` (or `.wic`) in it prints a warning, which
  usually means a wrong path:

  ```text
  Warning! No cwl files found in /home/you/empty-tools.
  Check 'search_paths_cwl' in your config file
  This almost certainly means you are not in the correct directory.
  ```
- Every tool found is read, once per compile. `--validate_plugins` also
  validates each with cwltool, which is slow for a large collection.

Namespaces keep two collections apart. A step runs a tool from the `global`
namespace unless its `wic:` block says `namespace: <name>`:

```yaml
steps:
- id: min.wic
wic:
  steps:
    (1, min.wic):
      wic:
        namespace: alternate
```

with `"alternate": ["/home/you/workflows/collaborator"]` under
`search_paths_wic`. Within one namespace, stems should still be unique. The
`gpu` namespace is listed by the configuration Sophios writes, empty, for
tool collections that keep GPU variants apart.

## Inference settings

`renaming_conventions` and `inference_rules` refine edge inference on the
command line. The first is a list of `[before, after]` renamings that
the naming conventions, on unless `--no_inference_naming_conventions` is given,
apply to an input's name before pairing it with an output's; [Edge inference](edge-inference.md) shows one
at work. The second maps a file format to `break` or `continue`, the
default, for the converter steps `--insert_steps_automatically` adds, and
stops the backwards search at them. A step you wrote carries its own
`inference:` rules in its `wic:` block. The values Sophios writes are GROMACS
conventions, for the molecular-modelling tools of its own collections;
replace them for your tools.

## The Python API and the configuration

The Python API reads no configuration file. `Step(clt_path=...)` reads the
tool at that path, which is why the Python examples name the shipped tools
as `Path.home() / 'wic' / 'cwl_adapters' / <tool>`. The inference settings are arguments instead:
`Workflow.compile()` and `Workflow.run()` take
`inference=Inference(...)`, where `renamings=` holds the renamings and
`format_rules=` the format rules, as [Edge inference](edge-inference.md)
shows. They are empty unless you pass them, where the command line takes
both from the configuration file, and `format_rules=` needs
`insert_steps=True`, as the rules are read only for an inserted step.

To name tools by stem in Python, as `.wic` does, build a registry from the
configuration and pass it:

```python
from pathlib import Path

from sophios import input_output, plugins
from sophios.api.python.workflow import Step, Workflow

config = input_output.get_config(None, Path.home())    # ~/wic/global_config.json
tools = plugins.get_tools_cwl(config)
touch = Step(clt_path='touch.cwl', tool_registry=tools)   # found by stem
```

With `insert_steps=True`, Python inserts only the converters among the tools
in `tool_registry=`, the ones named `insert_steps_automatically_*`; the command
line searches every tool on its search paths. Pass the registry to get the
same set:

```python
from sophios.api.python.workflow import Inference

workflow.compile(tool_registry=tools, inference=Inference(insert_steps=True))
```

`Workflow.from_wic(path, tool_registry=tools, workflow_paths=plugins.get_yml_paths(config))`
reads a `.wic` file with the same tools and workflows the command line would
find.

## Editor support

`sophios --generate_schemas` writes the JSON Schema of the `.wic` language to
`schemas/wic.json` in the base path, `autogenerated/schemas/wic.json` unless
you pass `--basepath`. It is generated from the parser's own definition
of the language. It describes syntax only, so it is the same on every machine
and never goes stale when tools change; whether a step names a tool that
exists here is decided when the workflow is compiled. Point your editor's
YAML schema setting at it for `*.wic` files. Because JSON has no YAML tags,
the schema describes the desugared spelling (`{wic_inline_input: value}`), and
a validator sees `!ii value` as a plain value; the schema catches structural
mistakes and admits everything else.

## Recap

`~/wic/global_config.json` lists the directories `.wic` steps search for
tools and workflows, by namespace, and two inference settings. Add a
directory to `search_paths_cwl` or `search_paths_wic` to name its files by
stem. The Python API reads no configuration: it names tools by path, or by
stem through a registry you build, and takes inference settings as
`Inference(...)`.
