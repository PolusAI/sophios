# Command-line reference

What does each flag of the `sophios` command do? This page lists the flags,
grouped by what they affect. A flag is spelled with underscores
(`--run_local`); abbreviations are not accepted, and an unknown flag is an
error unless `--passthrough_flags yes` sends it to the runner.

```text
sophios --yaml WORKFLOW (--generate_cwl_workflow | --check | --run_local | --generate_run_script) [options]
sophios --generate_config | --generate_schemas | --explain CODE | --version | --help
```

## What to do

Exactly one of the four, with `--yaml`:

| Flag | Effect |
|---|---|
| `--generate_cwl_workflow` | compile, and write the CWL and job file under the base path (`autogenerated/` unless `--basepath`): `<workflow>.cwl`, `<workflow>_inputs.yml` and a `<workflow>~<step>.cwl` for each step ([Compiling to CWL](compiling-to-cwl.md#the-tree)); nothing is pulled or run |
| `--check` | compile, then check that this machine can run the result (the container engine when a step uses one, the input paths, the directories Sophios writes, the programs it calls; under `--target nextflow`, the input paths, that `nextflow` starts and, when a process has a container, that Docker works) and stop; nothing is pulled or run |
| `--run_local` | compile, check, pull every container image, and run the workflow with the CWL runner; under `--target nextflow`, compile, check, and run the pipeline with Nextflow, which pulls its own images ([Nextflow](nextflow.md#running-on-the-nextflow-target)) |
| `--generate_run_script` | compile, check, pull (for a CWL run), and write `run.sh`, the runner command, instead of running it |

Without one of them the command compiles and then asks for one. Under
`--target nextflow` the modes are `--check`, `--run_local` and
`--generate_run_script`, and with none of them the command writes the four
[Nextflow](nextflow.md) files. The standalone modes take no `--yaml`:

| Flag | Effect |
|---|---|
| `--generate_config` | write `~/wic/global_config.json` and copy the shipped tools and example workflows beside it; says so and exits if the file exists |
| `--generate_schemas` | write the `.wic` language's JSON Schema to `<basepath>/schemas/wic.json` (`autogenerated/schemas/wic.json` unless `--basepath`), for editors |
| `--explain CODE` | print what an error code (`wic011`, `api002`, ...) means and how to fix it; a code Sophios does not have is an error |
| `--version` | print the installed version |

## Input

| Flag | Default | Effect |
|---|---|---|
| `--yaml FILE` | | the workflow to compile: a `.wic` file, or with `--allow_raw_cwl` a plain CWL workflow |
| `--inputs_file FILE` | | a YAML mapping of workflow input names to values, merged into the job file; for a plain CWL workflow, its job file as it is |
| `--config_file FILE` | `~/wic/global_config.json` | the configuration to read; must exist, and is never generated |
| `--homedir DIR` | your home directory | where the default configuration is, `DIR/wic/global_config.json`; for a run started from inside a tool, where CWL has cleared `HOME` |
| `--lang_version VERSION` | inferred | pin the language version for this compilation; beats any `wic: lang_version` in the files |
| `--allow_raw_cwl` | off | under `--target cwl`, a `--yaml` file that is a plain CWL workflow is used as it is, not compiled; in a Sophios document, an untagged input value that names no workflow input is written into the CWL unchecked instead of being `wic011` |

## Compiling

| Flag | Default | Effect |
|---|---|---|
| `--inference_disable` | off | compile without edge inference; an unbound input stays unbound |
| `--inference_use_naming_conventions` | off | among outputs that match by type, prefer the one whose name pairs with the input's, after the configuration's `renaming_conventions` |
| `--inference_strict` | off | an inference choice between equal candidates (`wic042`, `wic043`) is an error rather than a note |
| `--insert_steps_automatically` | off | when nothing matches an input by format, insert one converter step from the tools named `insert_steps_automatically_*` on the search paths |
| `--validate_plugins` | off | validate every tool on the search paths with cwltool before compiling |
| `--cwl_inline_subworkflows` | off | write one flat workflow: each subworkflow call with nothing but `in` and `out`, whose child is not `wic: inlineable: false`, is replaced by the child's steps; the tools stay separate files, and each call that stays nested is named on stderr |
| `--cwl_inline_runtag` | off | write one self-contained file, `<workflow>.cwl`, in which every step's `run:` carries its process, tools and subworkflows alike; a local run runs that file |
| `--partial_failure_enable` | off | rewrite the compiled CWL so that a job exiting with a success code counts as success with `null` outputs and every step with required inputs runs only when they are not `null` ([Partial failures](partial-failures.md)) |
| `--partial_failure_success_codes CODE ...` | `0 1` | the exit codes that count as success under `--partial_failure_enable`; `0` is always one |
| `--partial_failure_success_codes_range LOW HIGH` | `0 1` | a range of such codes, `LOW` included and `HIGH` excluded |
| `--docker_remove_entrypoints` | off | a diagnostic, not for everyday runs: before a local run, rebuild every tagged local image without its `ENTRYPOINT`, to show which tools depend on one: a tool without its own `baseCommand` or `arguments` fails under it; it acts only on a local run, so it does nothing with `--generate_cwl_workflow` |

The four rewriting flags (`--cwl_inline_subworkflows`, `--cwl_inline_runtag`,
`--partial_failure_enable`, `--docker_remove_entrypoints`) are an error with a plain CWL workflow under
`--allow_raw_cwl`, since Sophios compiles nothing to rewrite.

## Running

| Flag | Default | Effect |
|---|---|---|
| `--cwl_runner RUNNER` | `cwltool` | `cwltool` or `toil-cwl-runner` |
| `--container_engine ENGINE` | `docker` | the command that runs containers: `docker`, `podman`, `singularity`, or another `docker`-compatible command; decides how images are pulled and what the runner is told |
| `--pull_dir DIR` | the working directory | where Singularity images are pulled |
| `--ignore_docker_install` | off | do not check that the container engine is installed and reachable; does not change whether a step uses a container |
| `--ignore_docker_processes` | off | do not check the number of running Docker Desktop processes, which above 1000 can make a run hang |
| `--cachedir DIR` | no cache | with cwltool, cache each step's outputs in `DIR`, so a step whose tool and inputs are unchanged is reused; a real-time analysis turns this on |
| `--outdir DIR` | `<basepath>/outdir_<runner>_<workflow>_<timestamp>` | the runner's output directory, made absolute |
| `--quiet` | off | with `--run_local` or `--generate_run_script`: pass `--quiet` to cwltool (never to Toil), which hides its own log; each tool's messages still print as the run goes, and the compiled CWL is unchanged ([Running](running.md#see-more-or-less-of-the-run)) |
| `--no_provenance` | off | do not ask the runner for its record of the run, `<basepath>/provenance/<workflow>/` (`--provenance`) |
| `--passthrough_flags yes` | `no` | send arguments Sophios does not recognise to the runner unchecked, the CWL runner or Nextflow; they also need `--run_local` or `--generate_run_script`, since nothing else runs the runner |

## Drawing

| Flag | Default | Effect |
|---|---|---|
| `--graphviz` | off | write `<basepath>/<workflow>.wic.gv`, its PNG, and cwltool's SVG of the compiled CWL; needs `dot` on `PATH`, else a `wic029` note and no drawing |
| `--graph_label_edges` | off | one edge per port, labelled with the output it carries, instead of one per pair of steps |
| `--graph_label_stepname` | off | label each box with its step's name in the compiled CWL instead of its `wic: graphviz: label` |
| `--graph_inline_depth N` | unlimited | draw the steps of subworkflows nested up to depth `N`; a deeper call is one box |
| `--graph_dark_theme` | off | white text, box outlines and inferred edges, for a dark background, and explicit edges in a lighter blue; without it they are black and explicit edges are `blue` |

## Output

| Flag | Default | Effect |
|---|---|---|
| `--target TARGET` | `cwl` | what to compile to: `cwl`, or `nextflow`, which writes the four [Nextflow](nextflow.md) files under the base path instead, and with `--run_local` runs them with Nextflow; an option of the other target, set away from its default, is an error |
| `--basepath DIR` | `autogenerated` | the directory, relative to the working directory, for everything Sophios generates: the compiled CWL and job file, or under `--target nextflow` the Nextflow files, the real-time plans, provenance, `output_<workflow>.json`, the run's log `run_<workflow>.log`, the drawings, the schema, and the default `--outdir`; made if missing, and must be writable (`wic021`); when it lies below a search path, other than the search path itself, nothing under it is read as a tool or workflow; `Workflow.run(basepath=)` in Python is the same. `run.sh` and `error_<workflow>.txt` are written to the working directory, and so is the default `cachedir/` of a real-time analysis |
| `--diagnostics FORM` | `text` | `text`, one line per diagnostic on stderr, or `json`, one JSON object per line with the keys `severity`, `code`, `kind`, `message`, `fix`, `file`, `line`, `column`, `end_line`, `end_column`, `step`, `index`, `port` ([Checks and errors](checks-and-errors.md)) |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | done; for `--check`, nothing is in the way of a run |
| `1` | a reported problem (its diagnostics are on stderr), a failure Sophios did not expect (one line on stderr, the traceback in `error_<workflow>.txt`), or no mode flag was given |
| `2` | a command-line error: an unknown flag, a missing file, a code `--explain` does not have |
| the runner's | a run that ended with that exit code |
| `130` | interrupted with Ctrl-C |

## The same options from Python

`Workflow.run(run_args_dict={...})`, and `Workflow.start()` and
`Workflow.run_async()` with the same arguments
([Follow a run from Python](running.md#follow-a-run-from-python)), take the running options
by flag name without the dashes, as strings:
`{'cwl_runner': 'toil-cwl-runner', 'outdir': 'results', 'quiet': 'no'}`.
Only `quiet`, `no_provenance`, `generate_run_script` and
`docker_remove_entrypoints` are yes/no switches (`yes`, `true`, `1` or `on`
turn one on); `quiet` is on unless you turn it off.
`inputs_file`, `cachedir`, `outdir`, `container_engine`, `pull_dir`,
`cwl_runner`, `generate_run_script`, `docker_remove_entrypoints`, `quiet`
and `no_provenance` are read by Sophios. Any other key becomes `--key value` on a command line
that Sophios parses first, so a Sophios flag name is consumed there and has no
effect on the run. Currently, for a switch such as `ignore_docker_install`,
the value is left over and reaches the runner as a stray `yes`. For a flag that
takes a value, such as `custom_net` or `graph_inline_depth`, the flag and its
value are both dropped without a message. For a flag with fixed choices, an
invalid value such as `{'diagnostics': 'x'}` exits the process with status 2
and `main: error: argument --diagnostics: invalid choice`, after the workflow
has been written. `Workflow.compile()`
takes `target=`, `lang_version=`, `tool_registry=` and `inference=`, and nothing else; `Workflow.to_nextflow()` takes the last three.
The inference flags map onto `Inference(enabled=, strict=, naming_conventions=, insert_steps=)`, and the
configuration file's `renaming_conventions` and `inference_rules` onto its `renamings=` and `format_rules=`, which are empty in Python unless passed, as it reads no configuration file;
`Workflow.run()`, `start()` and `run_async()` take the same `inference=`, and `target='nextflow'` to run the
[Nextflow](nextflow.md#running-on-the-nextflow-target) pipeline instead, where the CWL defaults above do not apply,
an option only a CWL run reads is refused, and any other key becomes `-<key> <value>` for Nextflow. The rewriting and partial-failure options are command-line only;
`Workflow.draw()` takes the drawing ones ([Drawing](drawing.md)).
