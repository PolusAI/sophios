# Command-line reference

What does each flag of the `sophios` command do? This page lists the flags,
grouped by what they affect. A flag is spelled with underscores
(`--run_local`); abbreviations are not accepted, and an unknown flag is an
error unless `--passthrough_flags yes` sends it to the CWL runner.

```text
sophios --yaml WORKFLOW (--generate_cwl_workflow | --check | --run_local | --generate_run_script) [options]
sophios --generate_config | --generate_schemas | --explain CODE | --version | --help
```

## What to do

Exactly one of the four, with `--yaml`:

| Flag | Effect |
|---|---|
| `--generate_cwl_workflow` | compile, and write the CWL and job file under `autogenerated/`; nothing is pulled or run |
| `--check` | compile, then check that this machine can run the result (the container engine when a step uses one, the input paths, the directories Sophios writes, the programs it calls) and stop; nothing is pulled or run |
| `--run_local` | compile, check, pull every container image, and run the workflow with the CWL runner |
| `--generate_run_script` | compile, check, pull, and write `run.sh`, the runner command, instead of running it |

Without one of them the command compiles and then asks for one. The
standalone modes take no `--yaml`:

| Flag | Effect |
|---|---|
| `--generate_config` | write `~/wic/global_config.json` and copy the shipped tools and example workflows beside it; says so and exits if the file exists |
| `--generate_schemas` | write the `.wic` language's JSON Schema to `autogenerated/schemas/wic.json`, for editors |
| `--explain CODE` | print what an error code (`wic011`, `api002`, ...) means and how to fix it; a code Sophios does not have is an error |
| `--version` | print the installed version |

## Input

| Flag | Default | Effect |
|---|---|---|
| `--yaml FILE` | | the workflow to compile: a `.wic` file, or with `--allow_raw_cwl` a plain CWL workflow |
| `--inputs_file FILE` | | a YAML mapping of workflow input names to values, merged into the job file; for a plain CWL workflow, its job file as it is |
| `--config_file FILE` | `~/wic/global_config.json` | the configuration to read; must exist, and is never generated |
| `--homedir DIR` | your home directory | where the default configuration is, `DIR/wic/global_config.json`; for a run started from inside a tool, where CWL has cleared `HOME` |
| `--lang_version VERSION` | inferred | pin the language version for this compilation; beats any `wic: lang_version` in the files |
| `--allow_raw_cwl` | off | a `--yaml` file that is a plain CWL workflow is used as it is, not compiled; in a Sophios document, an untagged input value that names no workflow input is written into the CWL unchecked instead of being `wic011` |

## Compiling

| Flag | Default | Effect |
|---|---|---|
| `--inference_disable` | off | compile without edge inference; an unbound input stays unbound |
| `--inference_use_naming_conventions` | off | among outputs that match by type, prefer the one whose name pairs with the input's, after the configuration's `renaming_conventions` |
| `--inference_strict` | off | an inference choice between equal candidates (`wic042`, `wic043`) is an error rather than a note |
| `--insert_steps_automatically` | off | when nothing matches an input by format, insert one converter step from the tools named `insert_steps_automatically_*` on the search paths |
| `--validate_plugins` | off | validate every tool on the search paths with cwltool before compiling |
| `--quiet` | off | give every tool that names no `stdout`/`stderr` a `<stem>.out`/`<stem>.err` to capture them in; with `--run_local` or `--generate_run_script`, also pass `--quiet` to cwltool (never to Toil) |
| `--cwl_inline_subworkflows` | off | write one flat workflow: each subworkflow call with nothing but `in` and `out`, whose child is not `wic: inlineable: false`, is replaced by the child's steps; the tools stay separate files, and each call that stays nested is named on stderr |
| `--cwl_inline_runtag` | off | write one self-contained file: every step's `run:` carries its process, tools and subworkflows alike |
| `--partial_failure_enable` | off | rewrite the compiled CWL so that a job exiting with a success code counts as success with `null` outputs and every step with required inputs runs only when they are not `null` ([Partial failures](partial-failures.md)) |
| `--partial_failure_success_codes CODE ...` | `0 1` | the exit codes that count as success under `--partial_failure_enable`; `0` is always one |
| `--partial_failure_success_codes_range LOW HIGH` | `0 1` | a range of such codes, `LOW` included and `HIGH` excluded |

`--docker_remove_entrypoints` rebuilds local images without their `ENTRYPOINT`,
to show which tools depend on one: a tool without its own `baseCommand` or
`arguments` fails under it.

The four rewriting flags (`--cwl_inline_subworkflows`, `--cwl_inline_runtag`,
`--partial_failure_enable`, `--docker_remove_entrypoints`) are an error with a plain CWL workflow under
`--allow_raw_cwl`, since Sophios compiles nothing to rewrite.

## Running

| Flag | Default | Effect |
|---|---|---|
| `--cwl_runner RUNNER` | `cwltool` | `cwltool` or `toil-cwl-runner` |
| `--container_engine ENGINE` | `docker` | the command that runs containers: `docker`, `podman`, `singularity`, or another `docker`-compatible command; decides how images are pulled and what the runner is told |
| `--pull_dir DIR` | the working directory | where Singularity images are pulled |
| `--ignore_docker_install` | off | do not check that the container engine is installed and reachable; does not change whether a step uses a container |
| `--ignore_docker_processes` | off | do not check the number of running Docker Desktop processes, which above 1000 can make a run hang |
| `--cachedir DIR` | no cache | with cwltool, cache each step's outputs in `DIR`, so a step whose tool and inputs are unchanged is reused; a real-time analysis turns this on |
| `--outdir DIR` | `autogenerated/outdir_<runner>_<workflow>_<timestamp>` | the runner's output directory, made absolute |
| `--passthrough_flags yes` | `no` | send arguments Sophios does not recognise to the CWL runner unchecked; they also need `--run_local` or `--generate_run_script`, since nothing else runs the runner |

## Drawing

| Flag | Default | Effect |
|---|---|---|
| `--graphviz` | off | write `autogenerated/<workflow>.wic.gv`, its PNG, and cwltool's SVG of the compiled CWL; needs `dot` on `PATH`, else a `wic029` note and no drawing |
| `--graph_label_edges` | off | one edge per port, labelled with the output it carries, instead of one per pair of steps |
| `--graph_label_stepname` | off | label each box with its step's name in the compiled CWL instead of its `wic: graphviz: label` |
| `--graph_inline_depth N` | unlimited | draw the steps of subworkflows nested up to depth `N`; a deeper call is one box |
| `--graph_dark_theme` | off | black text and inferred edges, for a light background |

## Output

| Flag | Default | Effect |
|---|---|---|
| `--diagnostics FORM` | `text` | `text`, one line per diagnostic on stderr, or `json`, one JSON object per line with the keys `severity`, `code`, `kind`, `message`, `fix`, `file`, `line`, `column`, `end_line`, `end_column`, `step`, `index`, `port` ([Checks and errors](checks-and-errors.md)) |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | done; for `--check`, nothing is in the way of a run |
| `1` | a reported problem (its diagnostics are on stderr), a failure Sophios did not expect (one line on stderr, the traceback in `error_<workflow>.txt`), or no mode flag was given |
| `2` | a command-line error: an unknown flag, a missing file, a code `--explain` does not have |
| the runner's | a run that ended with that exit code |
| `130` | interrupted with Ctrl-C |

## The same options from Python

`Workflow.run(run_args_dict={...})` takes the running options
by flag name without the dashes, as strings, with `yes`/`no` for a switch:
`{'cwl_runner': 'toil-cwl-runner', 'outdir': 'results', 'quiet': 'no'}`.
`inputs_file`, `cachedir`, `outdir`, `container_engine`, `pull_dir`,
`cwl_runner`, `generate_run_script`, `docker_remove_entrypoints` and `quiet`
are read by Sophios. Any other key becomes `--key value` on a command line
that Sophios parses first, so a Sophios flag name is consumed there and ignored.
For a switch such as `ignore_docker_install`, the value is left over and
reaches the runner as a stray argument. For a flag that takes a value, such as
`custom_net`, `diagnostics` or `graph_inline_depth`, the flag and its value
are both dropped without a message. `Workflow.compile()`
takes `lang_version=` and `tool_registry=` and nothing else: inference runs
with the defaults, and the drawing, rewriting and partial-failure options are
command-line only.
